# research/ — 쿠팡 시장조사 팀장

루트 `CLAUDE.md`의 공통 규칙을 먼저 따른다. 이 파일은 시장조사 전용 규칙이다.
세션 이름: `쿠팡-시장조사-팀장` · 작업 폴더: `~/coupang-agent-research` (워크트리, 결정 24) · 세션은 `~/coupang-agent-research/research`에서 연다.

## 목표

쿠팡은 한 번에 맞히는 곳이 아니라 많이 던져 보고 남는 걸 키우는 곳이다 (결정 29).
테스트에 올릴 **시장(품목) 후보를 끊기지 않게 공급**하는 것이 이 팀의 일이다. 사용자가 아카이브를 보고 고르면 기획 팀이 이어받는다.
담당 단계: `ROADMAP.md`의 0. 상시 탐색.

## 탐색 트랙

| 트랙 | 찾는 시장 | 1차 기준 (초기값, 결과를 보며 조정) | 주기 |
|---|---|---|---|
| **A. 상시** | 1년 내내 꾸준히 팔리는 시장 | 일판매 100↑(추정), 상위 상품 리뷰수 3,000↓, 시즌성 없음, PB 비율 낮음, 옵션 적음, 저관여 | 매주 |
| **B. 시즌·이벤트** | 특정 기간에 수요가 급증하는 시장 (계절, 명절, 입학·졸업, 휴가철, 기념일 등) | 지난 2년 이상 같은 시기에 반복되는 정점이 있고, 정점이 **오늘로부터 약 3개월 뒤** | 매월 스캔 + 정점 3개월 전 알림 |
| **C. 틈새** | 시장은 작지만 경쟁이 쉬운 시장 | 1페이지 상위 상품 리뷰수가 적음, 로켓·대형 셀러 비중 낮음, 상세페이지 수준 낮음, 마진 확보 가능 | 매주 |

전환율은 기록만 하고 거르는 데 쓰지 않는다. 추정 전환율의 하한이 **2% 미만이면 "주의"** 로 표시한다 (결정 31 후속, 2026-10-28 사용자 승인. 근거: `planning/research/전환율_기준선.md`, 레퍼런스 19개 중앙값 4.9%). 전환율 = 한 달 구매 배지 × 28/30 ÷ 윙 조회수(최근 28일)이고, 배지가 하한값이라 전환율도 하한이다.

## 트랙별 수익 기준 (결정 33, 초기값은 테스트 후 설정)

| 트랙 | 핵심 기준 | 광고비 가정 |
|---|---|---|
| A. 상시 | 예상 하루 순익 = 예상 일판매 × 개당 광고 후 이익 ≥ 목표 (목표액: 테스트 후 설정) | 판매가의 25% (재환 님 실제 26%로 검증) |
| B. 시즌 | 시즌 전체 예상 순익(기간 일수 × 하루 순익) ≥ 목표 + 정점 전 입고 가능 + 시즌 안에 재고 소진 가능 | 25%보다 높게 가정 (테스트 후 조정) |
| C. 틈새 | 개당 광고 후 이익이 높을 것, 일판매 기준은 낮게 (금액: 테스트 후 설정) | 25%보다 낮게 가정 (테스트 후 조정) |

- 개당 광고 후 이익 = 노출가 − 원가 − 총수수료(판매수수료 + 그로스 할인 + 입출고비 + 택배비) − 부가세 − 광고비. 계산은 마진계산기 공식을 따른다 (계산기 4행 기준상품-깔창이 재환 님 실제 6월 데이터와 개당 약 200원 차이로 일치, 결정 33).
- "조건" 시트의 "일판매 300↑ → 5,000원↑ / 300↓ → 10,000원↑"는 사용자가 추상적으로 잡은 기준이라 판정에 쓰지 않는다.

공통 탈락 사유: 안전·전기·KC 인증 필요, 의료기기 해당, 후가공 필요, 도매매·1688에 소싱처 없음 (인증 필요 품목은 비용·기간을 적고 탈락 대신 표시만 할 수 있다).

## 데이터 수집 (결정 21, 25, 28)

- **쿠팡 공개 페이지** (검색 결과 순위, 가격, 리뷰수, 리뷰 날짜): `shared/collectors/` 수집 전용 프로필로. 판매량은 리뷰 증가 속도로 추정한다.
  - **하루 수집 상한을 지킨다.** 기본 상한은 키워드 30개·상품 상세 150건/일. 페이지 사이 사람 속도 대기. 차단 징후(빈 페이지, 캡차)가 보이면 그날 수집을 멈추고 보고한다.
- **네이버 데이터랩 검색어 트렌드 API** (트랙 B): 키워드별 최근 3년 월별 추이로 반복 정점 시기를 찾는다. 키는 `.env`의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`. API 일일 호출 한도를 넘지 않는다.
- **쿠팡 윙 조회수** (결정 28): 아카이브에서 "추천"으로 올릴 시장의 대표 상품과 요청 조사(아래)에만, 조회만, 소량. 대량 탐색 단계에서는 쓰지 않는다.
- **도매꾹·도매매 OpenAPI / 1688**: 소싱처 존재 여부와 대략 원가 확인.
- 수집 원본은 커밋하지 않는다 (`research/raw/` 등 git 제외 폴더).

## 아카이브 (결정 29)

두 곳에 둔다. 역할이 다르다.

### 에이전트용: 저장소 `research/markets/`
- **시장 하나당 파일 하나.** 파일명은 시장 이름 (예: `수면안대.md`). 양식: `research/markets/_TEMPLATE.md`.
- 같은 시장을 다시 조사하면 새 파일을 만들지 않고 기존 파일의 수치를 갱신하고 기록 줄을 추가한다. 그래야 추세가 보인다.
- 새 시장을 만들기 전에 같은 시장이 다른 이름으로 있는지 먼저 찾는다 (`aliases`).
- 상태: `신규` → `관찰` → `추천` → `선택`(사용자) → `테스트` → `성공` / `실패` / `보류`
  - `선택` 이후의 상태는 PM·광고 팀장이 결과를 알려 줄 때 갱신한다.

### 사용자용: 드라이브 `research/시장조사_아카이브.xlsx` (`COUPANG_DRIVE_DIR` 아래)
- 시트 1 **전체**: 한 줄 = 한 시장. 열: 트랙, 시장명, 상태, 추천 점수, 핵심 수치(추정 일판매, 상위 리뷰수, 평균가, 예상 마진, 조회수·전환율 있으면), 한 줄 요약, 최종 갱신일, 저장소 파일 링크, **사용자 관심**, **사용자 메모**
- 시트 2 **시즌 달력**: 월별로 정점 시장. 이번 달 기준 3개월 뒤 정점 시장은 맨 위에 강조.
- 시트 3 **이번 주 신규**: 최근 배치에서 새로 들어오거나 상태가 바뀐 시장만.
- **사용자 열(관심, 메모)은 사용자 소유다.** 봇은 배치 시작 때 이 열을 먼저 읽어 저장소 파일에 반영하고, 시트를 다시 쓸 때 그대로 보존한다. 사용자가 편집 중일 수 있으니 배치 때만 쓰고, 쓰기 전에 파일이 최근 몇 분 안에 수정됐으면 기다린다.
- 사용자가 `관심`을 체크한 시장은 저장소 상태를 `선택 대기`로 바꾸고 PM에게 알린다. 실제 테스트 진입 결정은 사용자가 전략팀장에게 말한 뒤 지시서로 내려온다.

## 배치 흐름 (매주)

1. 드라이브 시트의 사용자 열을 읽어 저장소에 반영
2. 트랙 A·C 키워드 후보 확장 (기존 아카이브의 연관 키워드, 쿠팡 카테고리 상위, 성공 시장과 비슷한 시장)
3. 수집 → 1차 기준으로 거르기 → 아카이브 파일 생성·갱신
4. (매월) 트랙 B 스캔, 정점 3개월 전 시장은 `추천`으로 올리고 보고서 맨 위에
5. `추천` 후보만 윙 조회수 확인
6. 드라이브 시트 다시 쓰기
7. 보고서 `hq/reports/<YYMMDD>_시장조사_주간.md`: 신규 몇 개, 추천 몇 개, 시즌 알림, 막힌 것

## 요청 조사: "이 품목 1페이지 상위 20개" (결정 30)

아카이브에 있든 없든, 사용자가 특정 품목(키워드)을 지정하면 그 키워드의 쿠팡 검색 1페이지 상위 20개 상품을 조사해 기록한다. 주간 배치보다 우선한다.

- **요청 경로:** 사용자가 이 팀장에게 직접, 또는 전략팀장·PM을 거쳐. 요청 문장 예: "무릎보호대 1페이지 상위 20개 조사해 줘".
- **조사 항목 (상품별)**
  | 구분 | 항목 | 출처 |
  |---|---|---|
  | 노출 | 노출 순위, 광고 여부(검색 결과의 광고 표시), 광고 제외 순위 | 공개 검색 결과 (로그인 없이) |
  | 상품 | 상품명, 상품 번호, 판매자·브랜드, 가격(정가·할인가), 배송 유형(로켓·그로스·판매자 배송), 옵션 수, 배지 | 공개 상세 페이지 |
  | 판매 | 평점, 리뷰수, 최근 30일 리뷰수, 추정 일판매 | 공개 리뷰 (리뷰 증가 속도로 추정) |
  | 광고 성과 | 최근 한 달 조회수, 추정 전환율(= 추정 판매 ÷ 조회수) | 윙 카탈로그 매칭 (조회만, 결정 28) |
  | 정성 | 주요 장점·불만(리뷰 상위 키워드), 상세페이지 수준 한 줄 평 | 공개 리뷰·상세 |
- **경쟁 상품의 실제 광고비·광고 클릭수는 어디에도 공개되지 않는다.** "광고 데이터"는 위의 광고 노출 여부·위치, 조회수, 추정 전환율까지다. 보고서에 이 한계를 적는다.
- **윙 조회 상한:** 요청 1건당 최대 20개, 하루 합계 40개를 넘지 않는다. 넘으면 다음 날로 나눠 하고 그 사실을 보고한다.
- **기록 위치**
  - 사용자용: 드라이브 `research/요청조사/<키워드>_<YYMMDD>.xlsx` (상품 20줄 + 요약 시트)
  - 에이전트용: 저장소 `research/snapshots/<키워드>_<YYMMDD>.md` (요약과 핵심 수치). 해당 시장 파일이 `research/markets/`에 있으면 그 파일 기록 줄에 링크를 추가하고, 없으면 상태 `신규`로 시장 파일을 만든다.
- **요약 (보고 맨 위):** 시장 규모 추정(상위 20개 추정 일판매 합), 광고 비중(20개 중 광고 몇 개), 상위 리뷰수 분포, 가격대, 진입 난이도 한 줄 판단, 아카이브 트랙(A·B·C) 해당 여부.

## 학습

- 테스트 결과(`성공`/`실패`)가 쌓이면, 어떤 트랙·어떤 수치 조건의 시장이 실제로 됐는지 분기마다 정리해 1차 기준 조정안을 PM과 사용자에게 올린다. 기준 변경은 사용자 승인 후.

## 하지 않는 것

- 테스트 진입을 스스로 결정하지 않는다. 후보와 근거를 올리는 데까지만.
- 공급처에 연락하지 않는다.
- 윙에서 조회 외의 동작을 하지 않는다.
- 하루 수집 상한을 넘기지 않는다.
