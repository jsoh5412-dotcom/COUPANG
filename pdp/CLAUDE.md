# pdp/ — 쿠팡 상세페이지 제작 봇

루트 `CLAUDE.md`의 공통 규칙을 먼저 따른다. 이 파일은 상세페이지 작업 전용 규칙이다.

## 목표

결제율이 검증된 레퍼런스 상세페이지의 설득 구조를 차용해, 우리 제품의 쿠팡 상세페이지를 만든다.
레퍼런스는 우리 제품과 다른 품목일 수 있다. 품목 특징이 아니라 **결제를 만드는 장치**를 가져온다.

## 입력 (사용자가 주는 것)

| 입력 | 1순위 | 2순위 |
|---|---|---|
| ① 레퍼런스 상세페이지 | 쿠팡 상품 링크 | 상세 이미지 직접 업로드 |
| ② 우리 제품 공급처 상세페이지 (도매꾹·도매매·1688 등) | 링크 | 이미지 직접 업로드 |
| ③ 같은 제품을 파는 다른 판매자 리뷰 | 쿠팡 상품 링크 | 리뷰 캡처·복붙 |
| ④ 제품 누끼 이미지 | 렌더 완료 후 사용자가 제공 | — |

링크 수집이 막히면 바로 사용자에게 2순위 방법을 요청한다. 같은 수집을 다른 우회 방법으로 반복 시도하지 않는다.

## 품질 기준 (결정 42, 모든 상세페이지에 적용)

v1이 "누끼 + 글자 + 카드" 반복이라 슬라이드처럼 보여 다시 만든다. 규칙 위반 없이 빨리 만드는 것보다 **레퍼런스만큼 사고 싶게 만드는 것**이 목표다.

1. **사진이 주인공이다.**
   - 섹션의 절반 이상은 사진이 화면의 절반 이상을 차지한다. 글자·아이콘 카드로만 된 섹션은 전체의 3분의 1 이하로 한다.
   - 실사 장면 최소 6컷: 첫 화면 대표 장면, 문제 공감 장면(레퍼런스가 사진으로 한 공감 컷은 사진으로), 사용 장면, 질감·접사, 사용법 단계, 마무리 장면.
   - 출처: 공급처 상세의 사용·연출 사진(사용 허락 확인된 것), AI 생성 장면(제품 없는 인물·신체·욕실·배경, 콘텐츠 원칙 4), 그 위에 공급처 누끼를 조명·그림자·크기를 맞춰 합성. 손에 쥔 장면은 제품 없는 손 사진에 누끼를 합성한다.
   - 작거나 흐린 사진은 키워 쓰지 않는다.
   - **순서: 레파토리 먼저, 사진은 그다음.** 레퍼런스·리뷰로 설득 흐름을 먼저 짜고, 섹션마다 필요한 컷을 `shotlist.md`(컷 번호, 장면, 제품 등장 여부, 구도, 용도)로 뽑은 뒤 사진을 구한다. 가진 사진에 맞춰 이야기를 줄이지 않는다.
   - **구할 수 없는 컷은 이 순서로 대체한다.**
     1. 공급처 상세·옵션 사진, 같은 공급처의 다른 상품 페이지 (사용 허락 확인)
     2. 무료 상업용 스톡 사진 (Unsplash·Pexels 등, 라이선스 기록) — 제품 없는 장면
     3. AI 생성 장면 (제품 없는 인물·신체·욕실·배경) + 공급처 누끼 합성
     4. 그래픽으로 표현: 도식·아이콘·단면도·확대 원 등. 실물처럼 보이는 제품 그림은 만들지 않는다 (원칙 4)
     5. 그래도 안 되는 컷(제품이 실제로 쓰이는 모습이 꼭 필요한 컷 등)은 섹션의 **메시지는 유지하고 표현만 바꿔** 진행하고, `촬영필요.md`에 "실물 샘플로 찍을 컷"으로 남긴다. 본품 단계 실물 촬영 목록이 된다.
   - 경쟁사 상품 리뷰 사진은 어떤 경우에도 쓰지 않는다 (원칙 2).
2. **레퍼런스 디자인 문법을 따른다.** 사진 위 글자 겹치기, 밝음·어두움 리듬, 큰 숫자·강조, 섹션 길이 리듬을 `ref_analysis.md` 디자인 어법대로. 둥근 카드 남발 금지.
3. **첫 화면(처음 약 2,300px)에 힘을 몰아준다.** 대표 장면 + 제품 + 핵심 메시지 + 신뢰 장치. 여기서 레퍼런스보다 약하면 다시 만든다.
4. **비교 검수를 한다.** 완성하면 레퍼런스 상페와 우리 상페를 같은 폭으로 나란히 놓은 비교 이미지(`output/compare.png`)를 만들고, 섹션별로 "레퍼런스보다 약한 곳"을 `copy/check.md`에 적은 뒤 고친다. 비교 이미지는 결과물과 함께 올린다.
5. **화려한 그래픽을 적극 쓴다 (사용자 지시, 2026-11-01).** 레퍼런스와 잘 팔리는 쿠팡 상페에서 쓰는 그래픽 장치를 적극 가져온다.
   - 예: 확대 원(돋보기 접사), 화살표·흐름선, 비교 그래픽(좌우·전후 대비 표), 큰 숫자·배지·리본·스탬프, 그라데이션·광택·입체감 있는 타이틀, 형광펜 강조, 아이콘 인포그래픽, 물방울·가루 같은 효과, 사진 위 오버레이 라벨, 단면도·구조도.
   - 그래픽 **장치(표현 방식)**는 가져오고, 다른 상페의 이미지·도안·문장 자체는 복제하지 않고 새로 만든다 (콘텐츠 원칙 3).
   - 그래픽이 사진을 대신하지는 않는다. 사진 위에 얹거나 사진 사이를 잇는 용도다. 밋밋한 둥근 카드 반복은 여전히 금지.
6. **썸네일도 같은 기준이다.** 레퍼런스 썸네일 3~5개와 나란히 놓고 비교한다. 흰 배경 규정은 등록 때 확인한다.
7. **시간은 아끼지 않는다.** 시범은 한 제품에 몇 시간이 걸려도 된다.

## 테스트 세트 1 예외 (결정 37, 38)

- 테스트 세트 1(17개)은 아래 워크플로의 ★ 체크포인트(브리프·구조)를 건너뛰고 끝까지 만든다. 사용자는 완성본을 보고 수정을 지시한다. 콘텐츠 원칙과 표시·광고 자체 점검은 그대로.
- 누끼는 공급처 상세페이지의 실제 제품 사진에서 배경을 지워 쓴다 (사용자 제공을 기다리지 않는다).
- 같은 품목(수면안대 8개, 발각질제거기 4개, 필라테스양말 3개, 뒤꿈치패드 2개)은 레퍼런스·리뷰 분석을 품목 단위로 한 번 하고 제품별로 차별점만 바꾼다.
- 완성본(분할 이미지 + 썸네일)은 드라이브 `COUPANG_DRIVE_DIR/상세페이지/테스트세트1/<우선순위>_<계산기 제품명>/`에 저장하고, 상품 카드 상페 칸에 경로를 적는다.

## 워크플로

각 단계 산출물은 `projects/<제품슬러그>/` 아래에 저장한다. ★ 표시는 사용자 승인 후 다음 단계로 넘어가는 체크포인트다.

1. **레퍼런스 분석** → `analysis/ref_analysis.md`
   - 섹션 순서와 각 섹션의 심리적 역할: 후킹, 공감, 문제 증폭, 해결 제시, 권위·근거, 사회적 증거, 비교, 가격 정당화, 긴급성, 반론 처리, CTA
   - 반복되는 화법 패턴 (예: 질문형 후킹, 체크리스트형 공감, 숫자 강조)
   - 디자인 문법: 색 대비, 텍스트:이미지 비율, 섹션 길이 리듬, 강조 방식
   - 품목 고유 정보는 기록하지 않는다
2. **공급처 분석** → `analysis/source_spec.md`
   - 중국어는 번역. 긴 상세 이미지는 1,500~2,000px 단위로 잘라서 읽는다
   - 스펙, 구성, 성분·소재, 사용법, 인증을 정리하고 "검증된 사실 / 공급처 주장(미검증)"으로 분리
3. **리뷰 마이닝** → `analysis/review_insights.md`
   - 반복 언급되는 구매 이유 → USP 후보 (언급 빈도 포함)
   - 불만·불안 → 반론 처리 섹션 재료
   - 사용 맥락(누가, 언제, 어디서) → 실사 이미지 연출 재료
4. ★ **전략 브리프** → `brief.md`: 타깃 페르소나, 핵심 메시지 1개, USP 우선순위 3개
5. ★ **섹션 구조** → `structure.md`: 레퍼런스의 설득 흐름에 우리 제품 콘텐츠를 매핑. 섹션마다 역할, 카피 방향, 비주얼 구성, 제품 슬롯 유무, 예상 높이
6. **카피** → `prompts/04_copywriting.md` 절차대로: 고객 말 사전 → 많이 쓰기 → 별도 검수자 채점 → 마지막에 규정 점검. 산출물 `copy/final.md` 등. 시범·새 품목 첫 제품은 디자인 전에 카피를 사용자에게 먼저 확인받는다
7. **섹션 렌더** → `output/sections/section_XX.png` + `output/slots.json`
   - 제품 자리는 비워두고 나머지는 최종 디자인으로
8. **누끼 합성** → `output/final/section_XX.png`
9. **쿠팡 규격 출력과 QA** → 업로드용 분할 이미지, 모바일 가독성 점검

## 렌더링 원칙

- **텍스트는 이미지 생성 AI로 만들지 않는다.** 섹션은 HTML/CSS로 작성하고 Playwright(Chromium)로 PNG 렌더링한다.
- **제품 슬롯**: 제품이 들어갈 자리는 HTML에서 `data-slot="<이름>"` 요소로 표시한다. 렌더 시 각 슬롯의 좌표·크기를 `slots.json`에 기록하고, 렌더 이미지에서는 투명 또는 배경색으로 비워둔다.
- **누끼 합성**은 `slots.json` 좌표 기준으로 코드(Pillow)로 배치한다. 비율 유지, 슬롯 안 중앙 정렬, 바닥 그림자는 코드로 생성. 제품의 형태·색상을 보정하거나 변형하지 않는다.
- **AI 실사 이미지**(gpt-image-2 등)는 텍스트 없는 배경·인물·사용 장면만. 제품이 들어갈 장면은 제품 없이 생성 후 합성한다.

## 모바일 레이아웃 기준

- 기준 화면: 아이폰 세로 화면에서 확대 없이 읽혀야 한다.
- 렌더 폭은 설정값으로 둔다 (쿠팡 권장 가로폭은 Wing 가이드의 현재 값을 확인해 `pdp/config` 에 기록).
- 렌더 폭 기준 최소 크기 (중장년 타깃 기준. 젊은 타깃이면 브리프에서 조정):
  - 본문 글자: 폭의 약 3.8% 이상 (쿠팡 780px 폭 → 30px 이상. 폭 근거는 `config/coupang_spec.md`)
  - 소제목: 본문의 1.4배 이상, 헤드라인: 본문의 2배 이상
  - 행간 1.5 이상, 한 줄 15~18자 내외
  - 배경과 글자 대비 4.5:1 이상
- 한 화면(세로 약 1.8~2배 폭)에 메시지 하나. 빽빽한 표와 작은 글씨 각주를 피한다.
- 전체 길이: 25,000~50,000px.

## 폴더

```
pdp/
├── CLAUDE.md
├── package.json   # Playwright 의존성 (`npm ci`)
├── config/        # 렌더 폭, 쿠팡 규격, 폰트 설정
├── prompts/       # 단계별 작업 지침 (01 레퍼런스, 02 공급처, 04 카피, 05 이미지 연출). 리뷰 분석 지침은 `shared/reviews/review_usp.md`
├── scripts/       # render.mjs: HTML → 가로 780px 렌더·섹션 경계 분할
│                  # (예정) 슬롯 좌표 추출 `slots.json`, 누끼 합성, 쿠팡 규격 출력
├── templates/     # base.html 섹션 템플릿, components.css 디자인 토큰
└── projects/
    └── <제품슬러그>/
        ├── inputs/    # ref/, source/, reviews/, nukki/  (커밋 안 함)
        ├── analysis/
        ├── brief.md
        ├── structure.md
        ├── copy/
        └── output/    # (커밋 안 함)
```
