## 2. 실사이트 테스트 (사용자 PC)

### 절차
1. PC에서 이 저장소를 열고 `README.md`의 "PC 준비"를 마친다.
2. `start_chrome`으로 수집 전용 크롬을 띄운다. 1688은 사용자가 이 창에서 직접 로그인해 둔다 (쿠팡은 비로그인, 도매꾹은 API — 결정 21).
3. 아래 표의 링크마다 스크립트를 한 번씩 실행한다.
   - 막히면 재시도하지 않고 그대로 기록한다.
4. 결과마다 `manifest.json`을 확인한다.
   - `status`, `strategy`/`selectors`, `images_found`/`images_saved`, `reviews`
   - 이미지 폴더를 열어 실제 상세와 장수·순서가 맞는지 눈으로 확인한다.
5. 결과를 아래 표에 채워서 커밋한다.

### 쿠팡 리뷰 개편 마크업 (2026-10 확인)
- 리뷰 1개 = `#sdpReview article`. 옛 `sdp-review__article__list*` 클래스는 도움돼요 영역에만 남음.
- 별점: `i.twc-bg-full-star` / `twc-bg-half-star` 아이콘 개수. 본문: `span[translate=no]`. 제목: 본문 바로 앞 굵은 줄. 옵션: `[class*=line-clamp]`.
- 페이저: `div[data-page][data-start][data-end]` 안에 이전·1~10·다음 버튼. 다음 묶음은 마지막 버튼.

### 1688 메모 (2026-10 확인)
- 검색 결과 목록은 섀도 DOM 안에 있다 (`a[href*=offer]`를 일반 선택자로 찾으면 0건). 상품 링크는 사용자가 주는 것이 기본이라 수집기에는 반영하지 않음.
- 검색 페이지는 무거워 `domcontentloaded`가 30초 안에 안 올 수 있다. 상세 페이지는 문제없음.

## 3. 실사이트에서 예상되는 막힘 (검증 전 가설)

| 사이트 | 예상 지점 | 대응 |
|---|---|---|
| 쿠팡 | 자동화 브라우저 감지로 Access Denied (launch 모드에서 특히) | cdp 모드(사용자가 직접 띄운 크롬)를 기본으로 쓴다. 그래도 막히면 2순위 |
| 쿠팡 | 상세·리뷰 DOM 클래스명이 개편으로 바뀌었을 수 있음 | 결과가 `fallback:`이면 선택자를 갱신한다 |
| 쿠팡 리뷰 | 페이지 버튼 묶음(1~10) 넘어갈 때 '다음' 버튼 구조 | `NEXT_BLOCK` 선택자 확인 |
| 1688 | 비로그인 시 로그인 페이지로 이동, 슬라이드 캡차(滑动验证) | 전용 크롬에서 직접 로그인·캡차 해결 후 한 번만 재실행 |
| 1688 | 상세가 나중에 로드되거나 섀도 DOM·iframe 안에 있음 | 섀도 DOM·iframe 탐색 구현됨. 실제 구조 확인 필요 |
| 도매꾹 | 상세 이미지가 외부 이미지 호스팅에 있고 리퍼러를 검사 | 다운로드 시 리퍼러를 붙인다. 실패하면 manifest의 HTTP 코드 확인 |
