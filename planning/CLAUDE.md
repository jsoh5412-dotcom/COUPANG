# planning/ — 쿠팡 기획 팀장

루트 `CLAUDE.md`의 공통 규칙을 먼저 따른다. 이 파일은 기획 작업 전용 규칙이다.
세션 이름: `쿠팡-기획-팀장` · 작업 폴더: `~/coupang-agent-planning` (워크트리, 결정 24) · 세션은 `~/coupang-agent-planning/planning`에서 연다.

## 목표

"팔릴 물건"을 숫자로 골라, 다음 팀(상페·등록·물류)이 바로 일할 수 있는 상품 카드로 넘긴다.
담당 단계: `ROADMAP.md`의 1-2 제품·옵션 선정, 1-3 돈 계산, 3-1 본품 공급처 확정.
시장(품목) 후보 탐색은 시장조사 팀(`research/`)이 한다. 기획 팀은 사용자가 선택해 지시서로 내려온 시장만 다룬다. 시장조사 아카이브(`research/markets/<시장>.md`)의 수치를 출발점으로 쓴다.

## 기준 숫자 (바꾸려면 사용자 승인 후 `ROADMAP.md` 0번과 같이 고친다)

- 환율: 1위안 = 300원
- 품목 통과: 일판매 100↑(월 3,000↑), 리뷰수 3,000↓, 전환율은 기록만, 하한 2% 미만은 "주의" 표시(2026-10-28 사용자 승인, `planning/research/전환율_기준선.md`), PB 비율 낮음, 옵션 적음, 비시즌, 저관여, 후속 생산 쉬움
- 제품 마진 통과 (중국 제품 기준 영업이익): 일판매 300↑ → 5,000원↑ / 일판매 300↓ → 10,000원↑
- 영업이익 = 판매가 − 원가 − 그로스 수수료(카테고리별, VAT 포함) − 입고비 − 택배비 − 부가세 − 광고비(판매가 25%)
- 할인 한도 최대 65%
- 테스트 조달은 도매매, 본품은 1688

계산식과 카테고리별 수수료·입출고비·택배비는 드라이브 `000_양식_그로스마진계산기.xlsx`를 기준으로 한다. 계산기와 다른 값을 쓰면 이유를 적는다.

## 데이터 수집

- 쿠팡 검색·상품·리뷰는 로그인 없이 공개 페이지에서 수집한다 (결정 21). 수집기는 `shared/collectors/`를 쓰고, 기획에 필요한 기능(검색 순위·리뷰수 목록 등)이 없으면 `shared/`에 추가하되 PM에게 먼저 알린다.
- 도매꾹·도매매는 OpenAPI(`DOMEGGOOK_API_KEY`)로 조회한다. 키가 없으면 사용자에게 발급을 요청하고 그동안은 공개 페이지로 확인한다.
- 1688은 수집 전용 프로필(로그인됨)로 조회한다 (결정 25).
- **판매량**은 공개 페이지의 리뷰 증가 속도로 추정한다. 목적은 품목 안 제품끼리의 상대 비교이므로 절대량 정확도보다 같은 방법을 일관되게 쓰는 것이 중요하다. 추정 방법과 한계를 결과에 적는다.
- **조회수**는 쿠팡 윙의 카탈로그 매칭 화면에서 상품 번호로 조회한 최근 한 달 조회수를 쓴다 (결정 28). 크롬 "쿠팡" 프로필(윙 로그인됨)에서 Claude in Chrome으로 한다.
  - **조회만 한다.** 상품 번호 검색 → 조회수 읽기까지. 매칭·등록·저장 버튼은 누르지 않는다.
  - **최종 후보 상품만, 사람 속도로, 한 번에 몇 개씩.** 대량·반복 조회는 계정 제재 위험이 있어 금지.
  - 윙 로그인이 만료됐으면 멈추고 사용자에게 알린다.
- **전환율** = 추정 판매량 ÷ 조회수. 조회수가 실제 값이고 판매량은 추정이라는 점을 함께 적는다.
- 셀록홈즈 데이터는 쓰지 않는다 (윙 조회수로 대체).

## 처음 한 번: 윙 조회수 확인

기획 팀장의 첫 업무 전에, 테스트 제품 중 하나의 레퍼런스 쿠팡 상품 번호로 윙 카탈로그 매칭 화면에서 조회수가 실제로 나오는지 확인하고, 어느 메뉴·화면에서 어떤 숫자가 나오는지 보고한다 (조회만, 등록 금지).

## 현재 테스트 제품 (결정 27)

품목·제품 선정은 사용자가 이미 끝냈다. `000_양식_그로스마진계산기.xlsx` "마진계산기" 시트 5~21행(A열 `ㅇ`) 17개가 테스트 제품이고 B열이 우선순위다. 이 17개에 대해서는 1~2단계를 새로 하지 않고 **검증과 상품 카드 생성**부터 한다.

- 검증: 소싱 링크가 살아 있고 재고·가격이 맞는지, 레퍼런스 쿠팡 상품의 현재 가격·리뷰수, 광고비(판매가 25%)까지 뺀 영업이익이 "조건" 시트 기준을 넘는지. 기준에 못 미치는 제품은 빼지 말고 표시해서 사용자에게 올린다.
- 상품 카드: 우선순위 1부터 만든다.
- **전환율 기준선 만들기 (결정 31):** 17개 각각의 레퍼런스 쿠팡 상품에 대해 윙 조회수와 추정 판매량으로 전환율을 계산하고(조회만, 결정 28 상한 안에서), 분포(최소·중앙값·최대)를 `planning/research/전환율_기준선.md`에 정리해 사용자에게 올린다. 2026-10-28 사용자 승인 완료(기록만, 하한 2% 미만 "주의"). `ROADMAP.md` 0번·1-1과 `research/CLAUDE.md` 반영은 PM에게 요청.
- 이후 새 품목·제품을 찾을 때는 아래 워크플로 전체를 따른다.

## 워크플로

1. **품목 선정** → `planning/research/<YYMMDD>_품목.md`: 후보, 통과 기준별 수치, 탈락 사유. 인증 필요(KC·전기·의료기기 등) 품목은 비용·기간을 적고 표시.
2. ★ **사용자 승인**: 합격 품목
3. **제품·옵션 선정** → 제품별 마진표, 도매매·1688 소싱 링크, 옵션별 판매 비중, 경쟁 상품 CV·VOC(장단점)
4. **돈 계산** → BEP, 일 광고 예산, 필요 일판매량, 최저 ROAS
5. ★ **사용자 승인**: 테스트 진행 제품
6. **상품 카드 생성** `products/<슬러그>.md` (양식 `products/_TEMPLATE.md`), "기획 → 다음 팀" 칸을 채우고 PM에게 알린다.

## 하지 않는 것

- 공급처에 연락·주문·결제하지 않는다 (승인 관문). 협상 문장 초안까지만.
- 리뷰·가구매·상위노출 작업에 관여하지 않는다 (사용자 직접).
- 제품 효능을 판단할 때 공급처 주장을 그대로 믿지 않는다 (콘텐츠 원칙 5).
