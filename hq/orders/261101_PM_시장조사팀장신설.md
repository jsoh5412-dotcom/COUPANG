## 목표
세트 1 다음에 테스트할 시장 후보(세트 2 이후)를 미리 쌓는다. 상페 v3가 도는 동안 병렬로 시작한다. 규칙은 `research/CLAUDE.md`에 이미 있다.

## 작업 (PM)
1. 워크트리 `~/coupang-agent-research`를 만들고 `.env`를 PM 폴더 것으로 심볼릭 링크한다 (기획 팀장과 같은 방식, 키 값은 읽지 않는다).
2. 드라이브 `COUPANG_DRIVE_DIR/research/` 폴더와 `요청조사/` 하위 폴더가 없으면 만든다. `시장조사_아카이브.xlsx`는 시장조사 팀장이 첫 배치 때 만든다.
3. 사용자에게 세션 여는 법을 알려 준다: Code 탭 → 새 세션 → 이 컴퓨터 → 폴더 `~/coupang-agent-research/research` → `/rename 쿠팡-시장조사-팀장` → Remote Control 켜기.
4. 디스코드: 사용자에게 `#시장조사` 채널과 웹후크를 만들어 달라고 하고, 받은 값을 `.env`의 `DISCORD_WEBHOOK_RESEARCH`에 넣는다.
5. **수집 전용 프로필 분리 (결정 43).** 시장조사용 프로필 `~/.coupang-collector-research`(포트 9223, 127.0.0.1만)를 만들고, `shared/collectors/`가 팀별 프로필·포트를 고를 수 있게 한다(환경 변수나 인자). 하루 수집 상한(키워드 30·상세 150)은 모든 팀 합계로 세는 방법(공용 카운터 파일 등)을 넣고, `shared/collectors/README.md`에 적는다. 1688은 기존 프로필에서만.

## 시장조사 팀장 첫 지시 (사용자가 세션을 연 뒤 PM이 보낸다)
> `research/CLAUDE.md`와 루트 문서 읽고 첫 주간 배치를 해. 트랙 A·C부터. 세트 1 품목(발각질제거기·수면안대·뒤꿈치패드·필라테스양말·슬개골보호대)과 겹치지 않는 시장 중심으로 후보를 모으고, 아카이브(저장소 `research/markets/`, 드라이브 `시장조사_아카이브.xlsx`)를 처음 만들어. 수집은 시장조사 전용 프로필(결정 43)로 하고, 하루 상한은 상페 팀과 합계로 지켜. 트랙 B는 네이버 데이터랩 키가 들어오면 시작. 보고는 한국어로.

## 사용자가 할 일
- 세션 열기 (위 3번), 디스코드 `#시장조사` 채널·웹후크.
- 트랙 B(시즌)용 네이버 데이터랩 API 키: developers.naver.com → 애플리케이션 등록 → 사용 API "데이터랩(검색어트렌드)" → Client ID·Secret을 PM에게 전달해 `.env`의 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`에 넣는다. 급하지 않다 (트랙 A·C는 키 없이 된다).
