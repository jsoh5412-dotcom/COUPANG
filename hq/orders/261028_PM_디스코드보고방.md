# 지시서: 디스코드 보고방 1단계 (웹후크)

- 발행: 쿠팡-본부-전략팀장 · 2026-10-28
- 대상: 쿠팡-본부-운영팀장-PM
- 상태: 대기 (사용자 서버·웹후크 준비 후 시작)  <!-- 대기 → 진행 → 완료(보고서 링크) | 보류(사유) -->
- 관련 결정: DECISIONS.md #40

## 목표
팀장들이 진행 상황을 디스코드 서버 "쿠팡 본부"의 팀별 채널에 자동으로 올려, 사용자가 폰(DeX)에서 한눈에 보게 한다. 한 방향 보고만 한다(봇이 메시지를 받지 않음).

## 사용자가 먼저 할 일 (PM은 이 목록을 사용자에게 안내만)
1. 디스코드에서 서버 만들기: 이름 `쿠팡 본부`
2. 채널 만들기: `#pm`, `#기획`, `#상페`, `#시장조사`, `#등록`, `#물류`, `#광고`, `#알림`
3. 채널마다 웹후크 만들기: 채널 설정(톱니) → 연동 → 웹후크 → 새 웹후크 → 이름(예: 쿠팡-기획-팀장) → "웹후크 URL 복사"
4. 웹후크 URL을 맥북 PM 폴더 `.env`의 `DISCORD_WEBHOOK_*`에 붙여 넣기 (채팅·스크린샷으로 보내지 않는다)
5. 사용자 ID: 디스코드 설정 → 고급 → 개발자 모드 켜기 → 내 프로필 우클릭 → "사용자 ID 복사" → `.env`의 `DISCORD_USER_ID`

## 작업
1. `shared/notify/discord.py` (+ `README.md`): 팀 이름과 메시지를 받아 해당 웹후크로 보낸다.
   - 종류: `시작`, `완료`, `막힘`, `병합`, `요약`. `막힘`은 해당 팀 채널과 `#알림` 둘 다에 올리고 `<@DISCORD_USER_ID>` 멘션.
   - 이미지 첨부(상페 썸네일 등) 선택 지원. 디스코드 첨부 용량 한도 안에서만.
   - 웹후크 URL·키를 로그나 출력에 찍지 않는다. 실패해도 본 작업은 멈추지 않는다(경고만).
   - 같은 내용 반복 전송 방지, 분당 전송 수 제한.
2. 공통 규칙 반영 제안: 팀장이 언제 보고를 올리는지(작업 시작·완료·막힘, PR 병합, 드라이브 결과물 저장) 한 단락 초안을 PM 보고서에 적는다. `CLAUDE.md` 수정은 전략팀장이 한다.
3. 시험 전송: 채널마다 한 번씩 테스트 메시지, `#알림` 멘션 확인.
4. 팀장들에게 사용법 전달. 테스트 세트 1 진행 중인 기획·상페 팀장부터 적용.

## 완료 기준
- `shared/notify/`가 main에 있고, 8개 채널 시험 전송 성공, 보고서 `hq/reports/<YYMMDD>_PM_디스코드1단계.md`에 보고 시점 초안이 있다.

## 승인 관문
- 없음 (외부 반영은 사용자 소유 디스코드 서버에 보고 글을 올리는 것뿐).

## 하지 않는 것
- 텔레그램은 쓰지 않는다.
- 봇 계정 만들기, `--channels` 연결, 팀장 세션 터미널 이전은 2단계라 지금 하지 않는다.
- 팀장 봇끼리 대화하게 만들지 않는다.

## 마감
