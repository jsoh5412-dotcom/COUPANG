## 목표
지금은 PM과 상페 팀장이 맥북의 같은 `~/coupang-agent` 작업 폴더를 같이 쓰고 있어서, PM이 브랜치를 바꾸거나 파일을 고치면 팀장 화면에도 그대로 섞인다. git 워크트리로 세션마다 작업 폴더를 분리해 서로 간섭하지 않게 한다.

## 구조

| 세션 | 작업 폴더 (워크트리) | 세션을 여는 폴더 |
|---|---|---|
| 쿠팡-본부-운영팀장-PM | `~/coupang-agent` (기존, 그대로) | `~/coupang-agent` |
| 쿠팡-상페-팀장 | `~/coupang-agent-pdp` (신규) | `~/coupang-agent-pdp/pdp` |
| 이후 팀장 | `~/coupang-agent-<폴더명>` | `~/coupang-agent-<폴더명>/<폴더명>` |

## 작업
1. **상페 팀장 워크트리 생성.** `~/coupang-agent`에서 `git worktree add ~/coupang-agent-pdp -b pdp/base origin/main` (브랜치 이름은 PM 판단, 단 `main`은 PM 워크트리가 쓰므로 팀장 워크트리는 `main`을 체크아웃하지 않는다).
2. **`.env` 공유.** `.env`는 git 제외 파일이라 워크트리에 따라오지 않는다. 키를 여러 곳에 복사하지 말고, `~/coupang-agent-pdp/.env`를 `~/coupang-agent/.env`로 연결하는 심볼릭 링크로 만든다. 키 값은 읽거나 출력하지 않는다.
3. **팀장 작업 방식 규칙화.** 루트 `CLAUDE.md`의 협업 규칙에 아래를 반영한 브랜치를 올린다.
   - 팀장은 자기 워크트리에서만 일한다. 다른 워크트리 폴더의 파일을 건드리지 않는다.
   - 작업마다 `git fetch origin` 후 `origin/main`에서 새 브랜치(`<폴더>/<작업>`)를 따서 시작한다.
   - 브랜치는 원격에 푸시하고, `main` 병합은 PM이 PR로 한다.
   - 새 팀장을 만들 때 PM이 워크트리와 `.env` 링크를 먼저 만든다.
4. **이사 작업과의 순서.** 진행 중인 상페 저장소 이사(`261026_PM_상페저장소이사.md`)를 망가뜨리지 않는 순서로 진행한다. 워크트리 생성은 이사 작업 중에도 가능하지만, 이사 PR이 병합된 뒤 상페 팀장이 최신 `main`을 받을 수 있게 안내한다.
5. **동작 확인.** `git worktree list`로 두 워크트리가 보이는지, `~/coupang-agent-pdp`에서 `git status`가 깨끗한지, `.env` 링크가 열리는지(값 출력 없이) 확인한다.

## 완료 기준
- `~/coupang-agent-pdp` 워크트리와 `.env` 링크가 있다.
- 협업 규칙 변경이 PR로 올라가 있다.
- 보고서 `hq/reports/261027_PM_팀별워크트리.md`에 결과와, 사용자가 상페 팀장 세션 폴더를 바꾸는 방법(세션 화면의 폴더 → 폴더 변경 → `~/coupang-agent-pdp/pdp`)이 적혀 있다.
