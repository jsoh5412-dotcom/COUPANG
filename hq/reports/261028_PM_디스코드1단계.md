## 한 일
- **`shared/notify/discord.py` + `README.md`**
  - 팀(8채널)과 종류(시작·완료·막힘·병합·요약·시험)를 받아 팀 채널 웹후크로 보낸다. `막힘`은 팀 채널과 `#알림` 둘 다에 올리고 `DISCORD_USER_ID`를 멘션한다.
  - `--file`로 이미지를 첨부한다. 파일당 10MB(부스트 없는 서버의 웹후크 한도)를 넘으면 빼고 보낸다.
  - 웹후크 주소는 `.env`에서만 읽고 출력하지 않는다. 실패해도 종료 코드 0과 경고만 낸다.
  - 같은 채널에 같은 내용은 10분 안에 다시 보내지 않고, 채널당 분당 10건으로 제한한다.
  - 멘션은 사용자 한 명만 허용한다(`allowed_mentions`). `@everyone`은 눌리지 않는다.
  - 표준 라이브러리만 써서 venv가 없어도 된다.
- **오프라인 시험 (가짜 주소, 실제 전송 없음)**
  - dry-run: `막힘`이 팀 채널과 `#알림` 두 곳에 멘션과 함께 만들어지는 것 확인.
  - 키가 없거나 종류가 틀리거나 전송에 실패해도 경고만 내고 종료 코드 0, 주소는 출력되지 않음.
  - 로컬 테스트 서버로 첨부 전송 형식(multipart, `payload_json` + `files[0]`) 확인.
  - 중복 전송 차단(두 번째 생략)과 분당 10건 제한(12건 중 10건 전송) 확인.
- `shared/README.md`에 `notify/` 행 추가, 지시서 상태 `진행`.

## 막힌 것
- **`.env`에 디스코드 키가 없다.** `~/coupang-agent/.env`(팀장 워크트리는 이 파일을 링크로 씀)에 `DISCORD_` 줄이 하나도 없고, 파일 수정 시각이 2026-10-27 20:20이다. 저장이 안 됐거나 다른 파일에 넣은 것으로 보인다. 키 값은 열어 보지 않았다. 사용자가 PM 폴더 `.env`에 `DISCORD_WEBHOOK_*` 8개와 `DISCORD_USER_ID`를 넣고 저장하면 8채널 시험 전송과 `#알림` 멘션 확인을 한다.

## 공통 규칙 반영 제안 (전략팀장이 `CLAUDE.md`에 넣을 초안)

> **디스코드 보고 (결정 40).** 팀장과 PM은 `python3 shared/notify/discord.py <팀> <종류> "<메시지>"`로 자기 팀 채널에 보고한다. 올리는 때: 작업을 시작할 때(`시작`, 상품명·할 일 한 줄), 상품 하나의 단계를 끝내고 카드를 갱신했을 때(`완료`, 드라이브 결과물 경로, 상페는 썸네일 첨부), PR이 병합됐을 때(PM이 `병합`, PR 번호와 한 줄 요약), 사람이 필요해 멈췄을 때(`막힘`, 무엇이 필요한지 한 줄). 하루 끝이나 큰 묶음이 끝났을 때 PM이 `#pm`에 `요약`을 올린다. 보고 실패는 작업을 멈추지 않는다. 웹후크 주소와 키 값은 메시지에 넣지 않는다. 같은 내용을 여러 번 올리지 않는다.
