## 한 일
- **순서.** 상페 저장소 이사 PR(#2)을 먼저 병합(`99f5eaf`)한 뒤, 그 `main`을 기준으로 워크트리를 만들었다. 그래서 상페 팀장 워크트리에는 이사해 온 코드가 이미 들어 있다.
- **상페 팀장 워크트리.** `git worktree add --no-track -b pdp/base ~/coupang-agent-pdp origin/main`.
  - 브랜치 `pdp/base`는 일부러 `origin/main`을 추적하지 않게 만들었다(`--no-track`). 추적하면 팀장이 `git push`할 때 `main` 쪽으로 향할 수 있어서다.
- **`.env` 공유.** `~/coupang-agent-pdp/.env` → `~/coupang-agent/.env` 심볼릭 링크. 키 값은 읽거나 출력하지 않았다.
- **PM 워크트리.** `~/coupang-agent`는 `main`으로 돌려 두었다.
- **협업 규칙.** 루트 `CLAUDE.md` 협업 규칙에 워크트리 규칙을 넣은 브랜치 `hq/worktree-rules`를 PR로 올렸다.
  - 세션별 작업 폴더, 자기 워크트리에서만 작업, 팀장은 `main` 체크아웃 금지, `.env`는 링크로 공유, 새 팀장은 PM이 워크트리·링크를 먼저 만듦.
  - 작업 시작: 팀장은 `git fetch origin` 후 `git switch -c <폴더>/<작업> --no-track origin/main`. PM은 `git pull origin main`.
    기존 2번 규칙("작업 시작 전 `git pull origin main`")은 `main`을 체크아웃하지 않는 팀장 워크트리에서는 맞지 않아 이렇게 나눴다.
  - 작업 마무리: 브랜치 푸시 후 PM에게 알림, `main` 병합은 PM이 PR로.
  - `SETUP.md`의 "상페 팀장 세션을 `~/coupang-agent/pdp`에서 다시 열기"를 `~/coupang-agent-pdp/pdp`로 고쳤다.
